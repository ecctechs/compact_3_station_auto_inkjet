จัดรายการงานข้างล่างนี้ให้เป็นรายงานส่งหัวหน้า

$ARGUMENTS

## กติกาการจัด

**แยกหมวดตามหน้าของโปรแกรม** ไม่ใช่ตามชนิดของงาน หัวข้อที่ใช้บ่อยคือ
`หน้า ORDER LIST` · `หน้า ORDER DETAIL` · `หน้า TRANSFER` · `หน้า SETTING` ·
`หน้า SCAN BARCODE` — ถ้ามีหน้าอื่นในรายการก็เพิ่มหมวดได้

**หมวดสุดท้ายชื่อ `รอคอนเฟิร์ม` เสมอ** เก็บทุกข้อที่เป็นคำถาม ยังไม่ชัด
หรือรอข้อมูลจากคนอื่น ไม่ว่าจะเป็นเรื่องของหน้าไหน

**เลขข้อเป็น 1.1 / 1.2 / 2.1** เรียงต่อกันในแต่ละหมวด

**ยุบของยิบย่อยที่เป็นเรื่องเดียวกันให้เหลือข้อเดียว** เช่น "แยก Sort 2 ชั้น" +
"ชั้นแรกตาม Status" + "ชั้นสองตามเวลา" รวมเป็นข้อเดียว — หัวหน้านับ progress
เป็นหน้าและฟีเจอร์หลัก ไม่ได้นับรายข้อย่อย

## ข้อห้าม

- **ห้ามเพิ่มงานที่ไม่ได้อยู่ในรายการที่ส่งมา** ต่อให้รู้ว่ามีงานอื่นทำไปแล้วก็ตาม
- **ห้ามใส่สถานะ** ว่าเสร็จ / ไม่เสร็จ / กำลังทำ — เป็นรายการงานที่จะทำ
- **ห้ามแก้ถ้อยคำ** เก็บสำนวนเดิมของผู้เขียนไว้ แก้ได้เฉพาะคำพิมพ์ตกที่ชัดเจน
  และจัดตัวพิมพ์ใหญ่ของชื่อเฉพาะให้สม่ำเสมอ

## รูปแบบผลลัพธ์

ตอบเป็น plain text ในบล็อกโค้ด ก๊อปไปวางในไลน์ได้ทันที ห้ามใช้ตัวหนา ตาราง
หรือสัญลักษณ์ markdown ใด ๆ ในบล็อก

```
งานวันที่ <วันที่>

1. หน้า ORDER LIST
1.1 ...
1.2 ...

2. หน้า ORDER DETAIL
2.1 ...

3. รอคอนเฟิร์ม
3.1 ...
```

ถ้าไม่มีวันที่มาในรายการ ให้ใช้วันที่ของวันนี้แบบ d/MM/yy ปี พ.ศ.

## หลังบล็อก

บอกสั้น ๆ นอกบล็อกว่าแก้คำพิมพ์ตกอะไรไปบ้าง และถ้าเจอข้อที่**ขัดกันเอง**
หรือขัดกับสิ่งที่รู้จากโค้ดในโปรเจค ให้ชี้ให้เห็นตรงนั้น พร้อมเหตุผลสั้น ๆ
แต่**อย่าไปแก้ข้อความในบล็อกให้** ปล่อยให้เจ้าของรายการตัดสินใจเอง
