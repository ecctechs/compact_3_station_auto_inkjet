# ตรวจคิวค้างและตรวจ PLC ก่อนส่ง MK

## กู้คิวอย่างไร

ใช้เฉพาะคิวที่ขึ้นกำลังส่ง/ไม่ทราบผล ทั้ง Backend และโปรแกรมทุกสถานีต้องเป็นรุ่นเดียวกัน ห้ามใช้โปรแกรมเก่าร่วมกับรุ่นนี้

1. หยุดการผลิตส่วนที่เกี่ยวข้องตามขั้นตอนหน้างาน หยุด/ปิดโปรแกรมตัวอื่นที่อาจกำลังส่งงาน และรอให้คำสั่งที่ค้างจบก่อน คนตรวจต้องอยู่หน้าเครื่องจริง
2. ตรวจ Lot, โปรแกรม, ข้อมูลที่โหลด และสถานะเริ่มพิมพ์จริง กรณี MK ให้ตรวจทั้งหัวที่งานใช้ หากรับข้อมูลไปบางส่วนหรือไม่แน่ใจ ให้คงคิวไว้ ห้ามเดาว่าไม่ได้ส่ง
3. ที่ ST1 เลือกแถวงาน แล้วกด **ตรวจคิวค้าง** โปรแกรมแสดงเครื่อง รอบ และเลขคิว หากงานติดหลายเครื่องจะตรวจทีละเครื่อง
4. ระบุชื่อผู้ตรวจและสิ่งที่ตรวจพบ แล้วเลือกหนึ่งข้อ:
   - **เครื่องรับงานและพร้อมพิมพ์แล้ว**: บันทึกว่ารับงานแล้ว ไม่ส่งคำสั่งซ้ำและยังถือเครื่องอยู่ เมื่อพิมพ์เสร็จจึงกดปล่อยคิวตามปกติ
   - **ยืนยันว่าไม่เริ่มพิมพ์และพร้อมส่งใหม่**: คืนเป็น pending โดยไม่ส่งเครื่องทันที ต้องใช้การเริ่ม/รับคิวตาม flow เดิมเมื่อพร้อม คิวเครื่องอื่นและงานอื่นไม่ถูกล้าง
5. หากยังไม่แน่ใจ กดยกเลิก ไม่เลือกทั้งสองข้อ หาก API ไม่ตอบ ให้โหลดคิวใหม่ก่อนตัดสินใจ ห้ามถือว่าบันทึกไม่สำเร็จแล้วส่งงานใหม่เอง

ตัวโปรแกรมหยุดรับปุ่มและหยุด dispatcher ของตัวเองระหว่างเปิดหน้าตรวจ แต่ไม่สามารถหยุดอุปกรณ์หรือโปรแกรมที่เครื่องอื่นแทนผู้ตรวจได้ ช่องชื่อเป็นบันทึกผู้ตรวจ ไม่ใช่ระบบ Login/สิทธิ์ใหม่ ควรมอบหมายผู้รับผิดชอบกู้คิวตามขั้นตอนหน้างาน

Backend ตรวจรอบส่งเดิมใน transaction เดียวกับการบันทึกผล เก็บผู้ตรวจ เหตุผล เวลา และผลเดิมใน QUEUE_DISPATCH ไม่ลบหลักฐาน คำขอกู้ซ้ำต้องเป็นคำขอเดิม ส่วนผลจากผู้ส่งเก่าหลังการกู้ถูกปฏิเสธ แต่การปฏิเสธ API ไม่สามารถถอนคำสั่งอุปกรณ์ที่ถูกส่งไปแล้วได้

## เงื่อนไข PLC ใหม่

ทางส่ง MK จาก Order List ตรวจค่าที่ต้องใช้และ register map ก่อนเขียน ถ้าขาด Address จะไม่เขียนชุดนั้น หากเขียนไม่ผ่าน/อ่านกลับไม่ได้/อ่านกลับไม่ตรง จะไม่เรียกส่ง MK และแจ้งเหตุ คิวกลับ pending ตามทาง not_sent เดิม ไม่มีการส่งซ้ำอัตโนมัติ

ถ้าเขียนไปบาง register แล้วเกิดข้อผิดพลาด ค่าบางส่วนอาจเปลี่ยนใน PLC แล้ว ไม่มีการเขียนย้อนค่าโดยเดาเอง ต้องตรวจค่าหน้างานก่อนเริ่มอีกครั้ง เครื่อง UV ที่ส่งแยกกันยังทำตามผลของตัวเอง ไม่ลบผลสำเร็จของอีกเครื่อง

ขอบเขตนี้คือทางผลิต Order List เครื่องมือทดสอบ/ส่งตรงใน Order Detail ไม่ได้ถูกเปลี่ยนเป็นระบบกู้คิว และห้ามใช้ส่งทับระหว่างมีงานผลิต

## ตรวจแล้วและข้อจำกัด

- ทดสอบ Backend ด้วย PostgreSQL บน loopback แยกฐานจริง: กู้ซ้ำ กู้ชนกัน ผลจากผู้ส่งเดิม คำขอรอบเก่า rollback เมื่อ DB ล้มเหลว และไม่ย้อนสถานะงานที่อีกเครื่องยังไม่ทราบผล
- ทดสอบ C# ApiClient กับ Backend จริงของชุดทดสอบ และหน้า Order List กับ HTTP จำลอง
- ทดสอบ PLC จำลอง: เขียนผ่านแต่ค่ากลับผิด เขียนล้มเหลว อ่านล้มเหลว และ map ขาด
- หน้าตรวจสร้าง controls ใน Designer.cs, ทดสอบสร้าง/วาดและตรวจภาพแล้ว ยังไม่ได้เปิด Visual Studio Designer
- ยังไม่ทดสอบอุปกรณ์จริง จึงไม่รับรองว่าไม่มีบัคทุกกรณี ต้องทำ integration test หน้างานก่อนผลิตจริง
- เจ้าของตัวอ่านปุ่ม ST2/UV1 ยังรอผู้ใช้ยืนยัน จึงยังไม่เปลี่ยนการอ่านปุ่มจาก ST1/MK และ ST3/UV2
