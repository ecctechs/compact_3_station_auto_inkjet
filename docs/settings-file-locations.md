# ไฟล์ตั้งค่าเก็บไว้ที่ไหน

## ที่ใช้งานจริง — `C:\ProgramData\CompactInkjet\`

ไฟล์ตั้งค่าของเครื่องอยู่ที่นี่ทั้งหมด สามไฟล์ ทุกตัวผ่าน `AppSettingsFile.Resolve`

| ไฟล์ | เก็บอะไร | ตัวจัดการ |
|---|---|---|
| `Setting.config` | ค่าทุกอย่างในหน้า Setting — IP, path ฐานข้อมูล, MENU_LEVEL | `CustomSettingsManager` |
| `uv.config` | โฟลเดอร์ของเครื่อง UV ตั้งครั้งเดียวตอนติดตั้ง ไม่มีหน้าจอให้แก้ | `UvSettingsManager` |
| `patterns.xml` | pattern ในหน้า Edit Pattern | `PatternStore` |

อยู่ที่ ProgramData เพราะ Program Files เขียนไม่ได้ถ้าไม่ได้รันแบบ admin — กด Save
แล้วดูเหมือนสำเร็จ แต่ค่าหายตอนเปิดใหม่

**การบันทึกไปผ่าน `AppSettingsFile.SaveAtomic` ทุกไฟล์** เขียนลงไฟล์ชั่วคราวให้เสร็จ
ก่อนแล้วสลับเข้าที่ด้วย `File.Replace` คนอ่านจึงเห็นได้แค่ไฟล์เก่าครบหรือไฟล์ใหม่ครบ
ไม่มีจังหวะที่ไฟล์เหลือครึ่ง ๆ และของเดิมถูกเก็บเป็น `.bak` ไว้ข้าง ๆ ทุกครั้ง

## ที่ไปกับตัวโปรแกรม — ค่าตั้งต้นเท่านั้น

`Setting.default.config` ถูกก๊อปไปวางข้าง ๆ `.exe` ทุกครั้งที่ build และตัวติดตั้งก็ลง
ไฟล์นี้ให้ ใช้ครั้งเดียวตอนเครื่องยังไม่มีไฟล์ของตัวเอง หลังจากนั้นไม่มีผลอะไรอีก

`Resolve` หาของมาตั้งต้นให้ตามลำดับนี้ เจออันไหนก่อนใช้อันนั้น

1. ไฟล์ใน ProgramData — มีแล้วก็ใช้เลย ไม่แตะอะไรต่อ
2. ไฟล์ชื่อเดียวกันข้าง ๆ `.exe` — ทางย้ายของเครื่องที่ตั้งค่าไว้ก่อนจะมี ProgramData
3. `<ชื่อ>.default.<นามสกุล>` ข้าง ๆ `.exe` — เครื่องติดตั้งใหม่
4. ไม่มีเลย — `EnsureAppSettingsFile` สร้างโครงเปล่าให้ บันทึกค่าได้ตั้งแต่ครั้งแรก

## ห้ามตั้งชื่อไฟล์ค่าตั้งต้นว่า `Setting.config`

เดิมชื่อนี้ ทำให้ในเครื่องมีไฟล์ชื่อเดียวกันสองตัว แล้วเข้าใจกันว่า
`CopyToOutputDirectory=PreserveNewest` จะไม่ทับตัวที่แก้ไว้ **ซึ่งไม่จริง**

MSBuild เทียบว่า "ขนาดกับเวลาตรงกันไหม" ไม่ใช่ "ปลายทางใหม่กว่าไหม" build ซ้ำเฉย ๆ
ไม่ทับจริง แต่พอ `git checkout` / `git pull` / สลับ branch เขียนไฟล์ต้นทางใหม่ เวลา
ก็ไม่ตรงกัน แล้วมันก๊อปทับทันที ค่าที่ตั้งไว้ทั้งไฟล์หายเหลือสองคีย์

ยิ่งกว่านั้น `InkjetOperator/Setting.config` เคยถูก track ใน git และ **ไม่เหมือนกัน
ทุก branch** — `main`, `dev`, `refactor-db`, `unit-test` และอีกหลาย branch ไม่มีไฟล์นี้เลย
ส่วน `ui` มีคนละชุดคีย์ สลับ branch ทีไรไฟล์นี้ถูกเขียนใหม่หรือถูกลบทุกที

## ตัวติดตั้งไม่ลงไฟล์ที่เป็นข้อมูลของผู้ใช้แล้ว

`CompactDemo.vdproj` ตั้ง `RemovePreviousVersions = TRUE` การติดตั้งทับจึงถอนของเก่า
ออกก่อน ไฟล์ที่ตัวติดตั้งเป็นเจ้าของจะถูกลบแล้วลงใหม่เป็นชุด default ทุกครั้ง
เดิม `patterns.xml` อยู่ข้าง ๆ `.exe` pattern ที่หน้างานแก้ไว้จึงหายทุกครั้งที่อัปเดต

ตอนนี้ไม่มีไฟล์ที่ตัวติดตั้งลงอันไหนเป็นข้อมูลของผู้ใช้ — `Setting.default.config`
เป็นค่าตั้งต้น ส่วน `uv.config` กับ `patterns.xml` ที่ยังลงอยู่เป็นเพียงทางย้ายและ
ค่าตั้งต้นของเครื่องใหม่ ของจริงอยู่ที่ ProgramData ซึ่งตัวติดตั้งไม่แตะ

ข้อยกเว้นเดียวคือเครื่องที่เขียน ProgramData ไม่ได้จริง ๆ `Resolve` จะถอยไปใช้ไฟล์
ข้าง ๆ `.exe` ซึ่งการซ่อมแซมของ Windows Installer ทับได้ กรณีนั้นโปรแกรมเตือนตอนเปิด
อยู่แล้วว่าบันทึกการตั้งค่าไม่ได้

## เวลาสงสัยว่าโปรแกรมอ่านไฟล์ไหน

หน้าสถานะระบบโชว์ path ของโฟลเดอร์ตั้งค่าไว้ (`HealthMonitor`) และถ้าเผลอทับค่า
ให้กู้จาก `<ชื่อไฟล์>.bak` ในโฟลเดอร์เดียวกันก่อนทำอย่างอื่น
