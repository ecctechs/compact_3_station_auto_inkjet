# ST1 รอบ 3 — ลดการรอและข้อความซ้ำ

Branch: `codex/st1-queue-reliability` — 26 กันยายน 2026

## สิ่งที่เปลี่ยน

1. ตรวจการเชื่อมต่อ MK/UV คนละปลายทางพร้อมกัน จากเดิมต่อทีละเครื่อง; ถ้า IP/port ซ้ำกัน ตรวจครั้งเดียวในชุดนั้น ยังต้องผ่านเงื่อนไขเดิมก่อนเริ่มงาน
2. ปล่อยเครื่องแล้วมีคิวถัดไป: ST1 ตรวจและส่งคิวก่อนโหลดรายการงานทั้งหน้า ส่วน ST3 ยังฝากให้ ST1 ส่งตามเดิม
3. ถ้าขอรีเฟรชระหว่างส่งหรือระหว่างอ่านข้อมูล ระบบจำคำขอไว้และทำต่อเมื่อว่าง ไม่ทิ้งคำขอไปรอ Timer รอบถัดไป; กดซ้ำหลายครั้งรวมเป็นรอบเดียว
4. รอบปกติที่ไม่มีการส่ง ใช้ผลอ่านคิวชุดเดียวทั้งตรวจงานพร้อมส่งและวาดแถบสถานี จากเดิม ST1 อ่านสองครั้งเหลือครั้งเดียว ถ้ามีการส่ง/คืนคิว จะอ่านผลใหม่ก่อนวาด
5. ST1 ไม่แจ้งซ้ำว่าเครื่องว่างและกำลังจะส่ง ก่อนแสดงผลส่งจริง; เมื่องาน Reset ตำแหน่งหัวสำเร็จไม่ขึ้นข้อความสำเร็จซ้ำกับเครื่องว่าง แต่ถ้า Reset ไม่ผ่านยังเตือน
6. กดปุ่มช่วงที่ส่งอยู่รัว ๆ เตือนอย่างมากครั้งเดียวใน 5 วินาที; รวมคิวที่รอตรวจสอบหลายเครื่องเป็นข้อความเดียว และยังแสดงแต่ละครั้งแรกตามเดิม

ผลสำเร็จเดิมเป็นข้อความหายเองอยู่แล้ว รอบนี้ไม่ได้เปลี่ยนข้อผิดพลาดเป็นข้อความหายเอง กล่องยืนยันเริ่มงาน เลือกโปรแกรม/default และข้อผิดพลาดสำคัญยังอยู่ครบ

## ไฟล์หลัก

- `InkjetOperator/Views/OrderListUserControl.cs`: ส่งต่อหลังปล่อยเครื่อง, จำคำขอรีเฟรช, ลดการอ่านซ้ำและข้อความซ้ำ
- `InkjetOperator/Services/JobSendService.cs`: รวบรวมปลายทางก่อนตรวจพร้อมกัน
- `InkjetOperator/Services/ConnectionPreflight.cs`: ตรวจปลายทางอิสระพร้อมกันและไม่เปิดซ็อกเก็ตซ้ำในชุดเดียว

ไม่มีการเปลี่ยน schema, Designer/event wiring, จังหวะหน่วงหรือ protocol ของ MK/UV/PLC, ลำดับคิว และกฎรอบสองของ 22

## ผลทดสอบ

- Build solution ผ่าน ไม่มี compile error; warning MSB4078 เดิมสำหรับ installer `.vdproj`
- Backend regression 18/18 ผ่านบน PostgreSQL ฐานแยก รวม C# ApiClient และ regression ส่งพร้อมกันจากรอบ 2
- เพิ่มการทดสอบ preflight ด้วยตัวเชื่อมต่อจำลอง: เริ่มคนละปลายทางพร้อมกัน, ปลายทางซ้ำเชื่อมครั้งเดียว, ผลเรียงตามรายการ และเครื่องหนึ่ง error ไม่ทำผลอีกเครื่องหาย
- ใช้ `OrderListUserControl` จริงใน Windows message loop พร้อม HTTP จำลองทั้งหมด ทดสอบอ่านคิวครั้งเดียว, รวมคำขอรีเฟรช 10 ครั้งเป็นรอบเดียว, เก็บคำขอระหว่างส่ง, หยุดรีเฟรชเมื่อเริ่มส่งระหว่างโหลด และลำดับตรวจคิวก่อนโหลดรายการหลังปล่อยเครื่อง
- ชุดทดสอบหน้าจอปิดการเรียก production Load event เพื่อไม่เริ่ม Timer/PLC watcher และไม่ใช้ฐานหรืออุปกรณ์หน้างาน
- ไม่ใช่การตรวจภาพหน้าจอ/Designer และยังไม่ได้วัดเวลา MK/UV/PLC จริง

รันทดสอบหน้าจอ:

```powershell
dotnet run --project tests/OrderListRefreshRegression/OrderListRefreshRegression.csproj
```

ชุด Backend ใช้วิธีรันในเอกสารรอบ 1; ต้อง rebuild `tests/QueueClientRegression` ก่อนรัน

## ลองหน้างานแบบสั้น

1. ลอง 11/12/32 ตอนเครื่องว่าง จับเวลาจากยืนยันถึงส่งครบ เทียบเครื่องและเครือข่ายเดียวกันกับรุ่นก่อน
2. มีงานรอแล้วกดปล่อยเครื่อง: งานถัดไปควรเริ่มส่งโดยไม่รอโหลดรายการทั้งหน้า และไม่มีข้อความสำเร็จซ้อนก่อนผลส่ง
3. ระหว่างส่ง กดปล่อยเครื่องอื่นที่ว่างหรือค้นรายการ: เมื่อรอบส่งจบต้องอัปเดตต่อเอง ไม่มีการส่งซ้ำ/ข้ามคิว
4. กดปุ่มที่ยังส่งอยู่รัว ๆ: เห็นคำเตือนเดียวช่วง 5 วินาที เครื่องต้องไม่ถูกปล่อยกลางส่ง
5. ทดสอบกรณีขาดการเชื่อมต่อในสภาพแวดล้อมที่ควบคุมได้: ต้องเห็น error และคิวไม่หาย ผลไม่แน่นอนยังต้องตรวจเครื่องก่อนกู้คืน

ยังต้องใช้ Backend/โปรแกรมทุกสถานีชุดเดียวกันตามรอบ 1 และยังไม่มีหน้ากู้คืนคิวผลไม่แน่นอน จึงต้องจัดขั้นตอนกู้คืนและเทสเครื่องจริงก่อนใช้ Production
