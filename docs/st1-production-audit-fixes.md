# ST1: แก้ผลตรวจข้อ 1–4

## สิ่งที่แก้

1. `TcpManager`: จำกัดเวลาเชื่อมต่อและส่ง/รอคำตอบ MK ที่ 3 วินาทีต่อคำสั่ง ใช้ cancellation กับ socket จริง เมื่อหมดเวลาจะปิด connection และไม่ส่งคำสั่งที่รออยู่ต่อบน connection เก่าหรือใหม่ ผู้เรียกแต่ละรายได้รับคำตอบของคำสั่งตัวเอง คำสั่งและช่วงเว้น 50 ms เหมือนเดิม
2. `UvTcpService.LoadAndStartAsync` (ปรับตามตัวเลือก A วันที่ 2026-09-27): Load สำเร็จให้นับว่า “ส่งข้อมูลแล้ว” ผล Start รายงานแยก ถ้า Start ถูกปฏิเสธ ไม่ตอบ หรือปิด connection จะแสดงคำเตือนโดยไม่เปลี่ยนผลส่งข้อมูลเป็นล้มเหลว ถ้า Load ไม่ผ่านยังถือคิวตรวจตามเดิม ไม่ส่งอุปกรณ์ซ้ำเอง
3. `PushButtonSettings.Save` แจ้งตัวเฝ้าปุ่มเมื่อบันทึกครบแล้ว `PushButtonWatcher` โหลดค่าทันที รวมเปิด/ปิดใช้งาน ยกเลิกการใช้ผลอ่านที่ค้างจากค่าเก่า และใช้ค่าแรกหลังเปลี่ยนเป็นจุดตั้งต้น ไม่ถือเป็นการกด ถอด event เมื่อหยุดหรือ Dispose
4. `OrderListUserControl.MachineStatus`: เมื่อได้ snapshot คิวสำเร็จ ให้ใช้ผล Backend แทนข้อความชั่วคราวที่จบแล้ว เก็บข้อความระหว่างกำลังส่งไว้ ไม่ใช้ประวัติส่งเก่ายืนยันรอบหลัง Restore และแสดง not_sent เป็นส่งไม่สำเร็จ

ไฟล์ที่แก้ในรอบนี้: `TcpManager.cs`, `UvTcpService.cs`, `PushButtonSettings.cs`, `PushButtonWatcher.cs`, `OrderListUserControl.cs`, `OrderListUserControl.MachineStatus.cs` และชุดทดสอบ ไม่แก้ Designer, schema, protocol, ลำดับงาน หรือกฎกรณีเขียน PLC ไม่ผ่าน

## ต้องเทสหน้างานต่อ

1. ส่ง MK ปกติ ตรวจว่าแต่ละคำตอบมาทัน 3 วินาที จากนั้นจำลองสายหลุดในช่วงทดสอบ ตรวจว่าไม่ค้างและไม่ส่งซ้ำเอง
2. ส่ง UV ปกติและกรณี Start ไม่สำเร็จ: ถ้า Load ผ่านต้องขึ้น “ส่งข้อมูลแล้ว” พร้อมคำเตือน Start แยก แต่ถ้า Load ไม่ผ่านห้ามขึ้นส่งข้อมูลแล้ว
3. บันทึก M address ใหม่ กดจริง ตรวจว่าอ่านตัวใหม่โดยไม่ต้องปิดโปรแกรม บิตที่ค้าง 1 ตอนบันทึกต้องไม่ปล่อยคิว ต้องกลับ 0 แล้วกดใหม่
4. ปล่อย MK/UV2 พร้อมกัน ทดสอบงานสองเครื่องและกดรัว ต้องได้งานถัดไปถูกใบ ไม่ข้ามคิว
5. ล้างคิว/Restore งานเดิม ตรวจว่าไม่ติดสถานะส่งแล้วจากรอบก่อน

ยังไม่รับรอง Production ทั้งระบบ: ST1 อ่าน MK, ST3 อ่าน UV2; ยังไม่มีตัวอ่านปุ่ม ST2/UV1 ขั้นตอนกู้คิวไม่ทราบผลและการหยุดเมื่อเขียน PLC ไม่ผ่านยังต้องตกลงต่างหาก ไม่อยู่ในรอบนี้

## ปรับเกณฑ์ UV ตามหน้างาน — 2026-09-27

ผู้ใช้ยืนยันว่างานเข้าและพิมพ์ได้เมื่อ Load ผ่านแต่ Start ตอบ RS=1 และเลือก A: ใช้ผล Load เป็นผลส่งข้อมูล ไม่ได้ตีความ RS=1 ว่า Start สำเร็จ ผล Start เก็บแยกในประวัติคำสั่งเดิม (`start_confirmed`, `start_warning`) พร้อมข้อความเตือนใน Order List/Order Detail ไม่มี schema ใหม่

ทดสอบกับ TCP จำลองทั้ง Load ผ่าน/ไม่ผ่าน, Start ตอบรับ/ปฏิเสธ/เงียบ/ตัดสาย/ตอบผิดรูปแบบ และเชื่อม C# ApiClient กับ Backend ในฐานทดสอบแยกเพื่อยืนยันว่า Load ผ่าน + Start RS=1 สามารถบันทึกส่งข้อมูลและปล่อยคิวตามปกติได้ ไม่ยิงคำสั่งพิมพ์ซ้ำ

การแก้นี้ใช้กับการส่งรอบใหม่ คิวที่ถูกบันทึกเป็น unknown ไปแล้ว (เช่นคิว 293 ในภาพ) ไม่ถูกปลดหรือเปลี่ยนผลย้อนหลังอัตโนมัติ ยังไม่ได้แก้ข้อมูลหน้างาน

## คิว ST3 ถูกงาน ST1 แซง — 2026-09-27

- เดิม ST3 จองงาน 10 เป็น pending แล้วจบ แต่ ST1 ส่งเฉพาะ active ขณะเดียวกันปุ่มเริ่มที่ ST1 ขอคิวเฉพาะงานตัวเองได้โดยข้ามงานที่รอก่อน
- ตอนนี้ ST3 ขอเริ่มคิวหลังจองผ่าน ถ้าเครื่องว่างและงานเป็นหัวคิว Backend จะตั้ง active เพื่อให้ ST1 ส่งตามรอบตรวจคิวเดิม (ทุก 5 วินาที) ถ้าเครื่องไม่ว่างให้รอปล่อยเครื่องตามเดิม
- Backend ตรวจหัวคิวตาม `queued_at` (หรือ `created_at`) แล้ว `id` ภายใต้ล็อกเดิมทุกครั้ง ถ้างานที่ขอไม่ใช่หัวคิวจะตอบ `queued` โดยไม่คืนงานอื่นไปส่งด้วยข้อมูลผิดใบ
- งาน 10 จาก ST3 จอง UV2 ก่อนงาน 12 จาก ST1: UV2 ต้องทำงาน 10 ก่อน ส่วน MK ของงาน 12 ส่งได้เมื่อ MK ว่าง หลังปล่อย UV2 จึงถึงงาน 12
- ไม่เปลี่ยนคำสั่งเครื่อง, PLC, schema, การถือรอบสองของงาน 22 หรือกฎไม่ส่งซ้ำเองเมื่อส่งไม่ผ่าน/ไม่ทราบผล ไม่มีการแก้คิวเก่าย้อนหลัง

ทดสอบ Backend กับ PostgreSQL แยกบน loopback ผ่าน 22/22 รวมแซงคิวทั้งสองทิศ, กดพร้อมกัน, เวลาเข้าคิวเท่ากัน, งานสองเครื่อง, งาน 22 และคิวส่งไม่ผ่าน ส่วน WinForms regression ผ่านการขอคิวจาก ST3, การโหลดงาน ST3 ที่ไม่อยู่ในตาราง ST1, ส่ง MK แยกจาก UV2 และไม่หยิบ UV2 ที่ยัง pending ไปส่ง ทดสอบส่วนนี้หยุดที่สิทธิ์ก่อนส่งจริง ไม่มีการติดต่อเครื่องพิมพ์/PLC

ติดตั้งต้องอัปเดต Backend แล้ว restart และอัปเดตโปรแกรม ST1/ST3 ทั้งคู่ ก่อนลองงานใหม่ คิว pending ที่ค้างจากรุ่นเก่าไม่ถูกเริ่มเอง ให้ตรวจเครื่องและกดเริ่มงานใบเดิมจากสถานีต้นทาง ส่วนคิว active/unknown ต้องตรวจผลเดิมก่อน ห้ามล้างเพื่อทดลองส่งซ้ำ

วิธีเทสหน้างาน: ให้ UV2 ว่าง กดเริ่มงาน 10 ที่ ST3 แล้วกดงาน 12 ที่ ST1 ตรวจว่า UV2 รับงาน 10, MK รับงาน 12 และ UV2 ของงาน 12 ยังรอ จากนั้นปล่อย UV2 และตรวจว่าเปลี่ยนเป็นงาน 12 เพียงครั้งเดียว ทำซ้ำแบบกดใกล้กัน และสลับให้ ST1 เข้าคิวก่อนเพื่อยืนยันว่าเรียงตามเวลาเข้าคิว ไม่ได้ให้สิทธิ์สถานีใดตายตัว
